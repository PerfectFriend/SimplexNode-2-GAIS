### Правила ведения журнала (обязательны для обеих сторон)

1. Каждое новое сообщение добавляется **строго в конец** файла.
2. Сообщения не удаляются, не переписываются и не «исправляются задним числом».
3. Каждое сообщение начинается с заголовка следующего формата:

```
---
**[YYYY-MM-DD HH:MM TZ]** | От: [Имя] | Кому: [Имя] | Тип: [СООБЩЕНИЕ / ОТЧЁТ / АУДИТ / ЗАДАНИЕ / ЗАМЕЧАНИЕ / ПРИНЯТИЕ / ВОЗВРАТ]
**Тема:** краткая тема
```

4. После заголовка идёт тело сообщения.
5. В конце сообщения рекомендуется ставить разделитель `---` или просто оставлять пустую строку перед следующим заголовком.
6. Допускаются теги внутри текста: `[REAL]`, `[SIM]`, `[PROD-READY]`, `[NEEDS-WORK]`, `[SECURITY-CRITICAL]`, `[ЭТАП-N]` и т.д.
7. Этот журнал является основным каналом рабочей переписки по этапам. Отдельные «письма» вне журнала не создаются.

### Что решено по интерфейсу

1. **Главный экран = чат в стиле Telegram.**  
   Не панель с кучей кнопок внизу. Чат занимает основное пространство.

2. **Навигация** — из чата открывается единое меню (drawer / side / overflow), где:
   - чаты
   - сейф
   - сеть / нода / Tor
   - файлы / облако
   - настройки
   - логи

   Нижний navigation bar с постоянными крупными кнопками больше не центр вселенной. Он либо уходит, либо сжимается до минимума.

3. **Клавиатура** — по раскладке и габаритам максимально близка к Gboard, чтобы пальцы не переучивать.  
   Если системная Gboard уже решает задачу — не плодим кастом ради кастома. Кастом только если есть сильная причина.

4. **Украшательство** (цветные темы, скины, обои, орнаменты) — **в самом конце**, когда функционал закрыт.

5. **Радиоточка как индикатор здоровья ноды:**
   - играет → сеть/трафик в порядке, нода жива;
   - замолчало / alarm → что-то не так, смотри логи и чини.

   Это не игрушка в середине разработки, а финальный UX-сигнал (Этап 8).
