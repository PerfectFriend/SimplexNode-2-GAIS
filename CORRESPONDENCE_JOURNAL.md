Женя, важная смена курса. Это не претензия к тебе: ты сделал ровно то, что было в ТЗ Этапа 7. Владелец только что уточнил threat model — и она жёстче.

### Что сказал владелец

> Системная клавиатура должна быть **полностью удалена** как интерфейс ввода.  
> Делаем **свою внутреннюю** клавиатуру, копирующую эргономику Gboard.  
> Все вводимые данные остаются только внутри приложения.  
> Гуглу не доверяем слушать наш ввод.  
> Максимально автономная нода.

### Что это значит

1. Модель «Gboard по умолчанию + Air-Gap опционально» — **отменяется**.
2. **In-app keyboard — единственный** способ ввода в чате, PIN, seed, поиске, командах.
3. Системная IME не должна подниматься на этих полях.
4. Эргономика (раскладка RU/EN, размеры, shift/symbols/backspace/send) — как у Gboard, чтобы пальцы не переучивать.
5. Этап 8 (BIP-39 onboarding) **ждёт** эту клавиатуру: ввод seed/PIN только через неё.

### Вердикт по Этапу 7

Статус меняется: **ПРИНЯТ → НА ДОРАБОТКЕ (7-revised)**.

Работа, которую ты уже сделал (Air-Gap раскладка, Telegram input chrome, команды, bubbles) — не выкидываем. Наоборот: Air-Gap / in-app ветку **делаем основной и единственной**, системный TextField→IME путь выключаем.

### Задание 7-revised

1. Убрать показ system soft keyboard с основных input-полей (`showSoftInput` / focus → IME).
2. При фокусе на поле ввода — показывать **только** in-app keyboard panel.
3. Довести in-app keyboard до повседневной пригодности:
   - RU + EN
   - symbols / digits
   - shift, backspace, send/enter
   - габариты и зоны ≈ Gboard
4. Chat, PIN, future seed screens — все на этой клавиатуре.
5. Краткий отчёт: какие поля закрыты от IME, как устроена клавиатура, что ещё шероховато.

**Критерии приёмки:** системная клавиатура не всплывает в основных сценариях; набор RU/EN реален; эргономика узнаваема; сборка зелёная.

После приёмки 7-revised сразу продолжаем **Этап 8** (онбординг + RootKeyHub) — уже на правильном вводе.
